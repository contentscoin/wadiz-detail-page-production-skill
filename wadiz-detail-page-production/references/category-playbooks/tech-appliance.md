# Tech / appliance

Plan around the actual use problem, mechanism, independent benefits, source-backed specs, compatibility, operation, power, safety and service. `tech-appliance` and `appliance` remain legacy aliases for `tech`.

Use distinct feature sections when needed, a spec/option block, operation explanation, compatibility, warranty/service and offer. Comparison is useful only with evidence for both sides and the same conditions. Do not invent a "general product" baseline to force a comparison cut. Adaptive count replaces the old 12/15-feature-count default.

Battery time, noise, suction, load, durability and other performance numbers require actual product/test material. Keep test conditions alongside the claim. Actual certification evidence is required for marks and labels; never generate official proof. Exact specs, comparison figures, power and warranty copy use editable text layers.

GIFs from image sequences can explain buttons, assembly or options. Actual operation/performance proof uses supplied real footage. A generated animation of a mechanism is illustrative and cannot establish speed, noise, battery life or safety.

OpenCrab query: actual product term (for example earphone) plus topic, source-backed feature/spec/demo order, compatibility concerns and offer. Reject unrelated office furniture even if returned from a category-playbook pack.
