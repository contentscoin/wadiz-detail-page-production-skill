# Category × topic × product routing

Choose the primary product category before compiling the adaptive page plan. Category requirements define the information the buyer needs; topic changes the story and media purpose; actual facts, options, assets, and objections determine sections. Fixed 12/15 cuts are compatibility presets only.

| Canonical category | Playbook | Required planning emphasis |
|---|---|---|
| `food` | [food.md](food.md) | Ingredients, allergens, serving, storage, shelf life, delivery |
| `beauty` | [beauty.md](beauty.md) | Ingredients, intended use, actual tests, usage and cautions |
| `tech` | [tech-appliance.md](tech-appliance.md) | Specs, compatibility, operation, power, warranty and service |
| `fashion` | [fashion-accessory.md](fashion-accessory.md) | Fit, sizes, colors, materials, wearing context and care |
| `living` | [living-kitchen.md](living-kitchen.md) | Real size/capacity, use context, installation, cleaning and material |
| `service` | [service-membership.md](service-membership.md) | Deliverables, process, qualified people/proof, schedule and terms |

Historical names such as tech-appliance/appliance, fashion-accessory, living-kitchen, and service-membership are import aliases. [beauty-food-regulated.md](beauty-food-regulated.md) routes the old combined category to the actual food or beauty subject. [funding-maker.md](funding-maker.md) adds maker/reward/schedule requirements to the underlying category; funding is not a seventh product type.

For a hybrid, combine the necessary information and claim requirements rather than force one set of purchase concerns to disappear. If no category fits, flag the gap and ask for the meaningful classification instead of hiding it behind a generic template.

## Topics

| Topic | Structural effect | Useful GIF role |
|---|---|---|
| `gift` | Recipient/occasion, contents, presentation, delivery deadline | Package/component reveal; not a guaranteed delivery claim |
| `problem_solution` | Concrete situation, mechanism, usage, purchase objections | Step sequence or actual operation |
| `new_product` | What's new, familiar alternative, explanation and adoption | New feature/structure illustration |
| `premium` | Material/process, detail, justified value and provenance | Detail sequence; no invented craft history |
| `comparison` | Source-backed differences, fit criteria, tradeoffs | Option or feature contrast with identical conditions |
| `relaunch` | Verified changes, unchanged strengths, returning concerns | Old/new differences with real model/version facts |

Themes do not create facts. A gift topic needs actual delivery conditions; relaunch needs actual version-change evidence. Merge topic and category requirements, then use the product's SKU/options, facts, assets and buyer objections to decide section count/order. Record the choice and coverage in PagePlan.

## OpenCrab validation

Query the selected category with concrete product terms and the campaign topic. Require relevant source text and source/page/section links. Run the raw evidence checker before adopting results. An earphone/food/clothing query returning office furniture is a rejection, not a usable generic pattern. Retain the category-specific evidence gap even if other families pass.

Illustrative visuals may be generated; test results, certifications, ingredient tables, reviews, and real product-operation evidence require actual sources. Exact numeric/regulated copy is rendered with editable text layers and checked against approved facts.
